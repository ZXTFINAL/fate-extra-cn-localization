# v0.16.0 — 可重建工程包

> 这是**工程版本**，不新增译文、不改变 v15 的资源状态。目标只有一个：
> 任何人拿到仓库 + 自备正版 ISO，两条命令重建出完整中文镜像。

---

## 这一版解决什么

之前要复现，得从解包一路重跑到补字、图片重排，中间还依赖 macOS + Swift 渲染环境。
现在仓库里直接带好三样东西，把这条路压成两条命令：

| 新增 | 内容 | 体积 |
|---|---|---|
| `data/overlay/` | 375 个**改动过**的资源（字库表、小字表、UI 纹理） | 71.9 MB |
| `data/inventory/` | 15,962 个解包文件的路径/大小/校验和 | 160 KB |
| `scripts/quick/` | 一键重建与快速改稿工具 | 40 KB |

原始解包树 1.67 GB 不入库——它 99% 是未修改的原版资源，可以由 ISO 精确重现。

## 两条命令

```sh
cp /path/to/日版.iso iso/original.iso

python3 scripts/quick/quick.py bootstrap --iso iso/original.iso
python3 scripts/quick/quick.py rebuild
```

产物：`work/build/Fate_Extra_CN.iso` + `work/build/quick-build-report.json`。

`bootstrap` 全程不挂载、不写原盘：直接按 ISO9660 解析出 `PSP_GAME/USRDIR/data.cpk`，
再解 2,297 个 DAT/PAK/CMP，最后用 `data/inventory/` 的清单逐文件核对。

## 日常改稿

```sh
python3 scripts/quick/quick.py text find "セイバー"
python3 scripts/quick/quick.py text set --id <ID> --zh "……"
python3 scripts/quick/quick.py rebuild
```

`text set` 会顺带做字库覆盖检查：不在 CP932 也不在 `glyph-map` 的字会直接列出来——
这类字进游戏是空白，必须先补字。

改图走 `image decode` → 改配置 → `image apply` → `overlay sync` → `rebuild`。
纹理是调色板 + CCT 索引格式，不能直接覆盖 PNG，原因见 `docs/06-ui-images.md`。

## 校验

```sh
python3 scripts/quick/quick.py overlay verify    # 375 个文件逐个比对 SHA-256
python3 scripts/quick/quick.py inventory verify  # 解包树与基准清单比对
python3 scripts/quick/quick.py verify            # 产物哈希 + 仓库数据完整性
```

已知原盘：`60399d610cbcda96601374a2e621a22bb58505c403c6fa4221eec5e87235667b`
（Fate/Extra 日版 NPJH-50247，1.2 GB）。不同区域版本解包后可能有零填充差异，
`inventory` 会提示但不阻断。

## 关于 ISO

**本 Release 不附带 ISO。**

汉化补丁可以分发"改动过的文件"，但不能分发游戏本体或完整镜像。仓库里的
`data/overlay/` 是补丁负载，必须叠加在你自己的正版 ISO 上才有意义。
技术上也不需要附带：`rebuild` 用同一张原盘会产出字节一致的镜像，
`quick-build-report.json` 里的 SHA-256 就是可复核的凭证。

## 已知限制

- `bootstrap` 的解包阶段最慢（实测 13.8 分钟 / 1.67 GB），只需做一次；`rebuild` 约 11 分钟。
- 变更集对应 v15 资源状态；v15 尚未回写 ISO，实机回归仍未做（见 ROADMAP P9/P10）。
- 教程截图内部 UI、lane 2/3 语境校对仍为未完成项，与 v0.15.0 相同。
- `image decode` 依赖 Pillow + numpy；纯重建不需要。
