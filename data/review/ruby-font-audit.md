# Ruby 小字字库审计（2026-10-19）

结论：当前 `work/build/poem-v14-native-grid/data.cpk` 内的 `PRELOAD.pak/ruby.bin`、`ruby.txb` 与原字库逐字节相同。小字字库没有任何汉字。现行中文上标需要的 **913 个不同汉字、4262 字次**均不在小字映射中；正文 `kanzi.bin/font.txb` 的补字不会自动改变这套小字资源。

本审计直接使用 `tools/extract_fate_extra.py` 的 `parse_cpk/read_cpk_entry/decode_cmp` 读取当前 CPK，并在内存中解开 PRELOAD PAK，未依赖 `/tmp/fate-candidates` 缓存。仅做静态资源审计，无模拟器；未修改工具、翻译主数据或构建包。统计源为 `work/translation/text.jsonl`，SHA-256 `364e64be7bd174bbbf732721a393841a08cc0469b141f07026534ea58b1aec06`。

## 2. `ruby.bin` 格式

- 文件 1328 字节；`0x00` 为 little-endian `uint32` 条目数 **219**。
- 从 `0x04` 起，每条 **6 字节**：前 2 字节是 little-endian CP932 代码（例如 `45 81` 对应游戏文本字节 `81 45`，即 `・`）；后 3 字节是该字的 UTF-8 BMP 字符，第 6 字节为 `00`。219 条的 CP932 和 UTF-8 字段全部互相对应。
- 219 条表结束于 `0x526`，后面 10 字节均为零，文件对齐到 16 字节。
- 219 字仅覆盖假名、52 个全角 Latin 字母及 `・ーⅡ、` 等；**汉字数为 0**。准确全表和示例记录见同目录 JSON。
- 表的顺序就是 atlas 字形索引；前 196 字在第 0 页，索引 196 的 `ン` 是第 1 页左上角，末字索引 218 为 `、`。

## 3. `ruby.txb` 与 glyph 规格

这是带路径的 PAK：`uint16 count=2`、`uint16 flags=0x8000`，随后为两条 `uint32` 长度、16 字节对齐，再按条目依次存放 **64 字节名字 + TEX**。

| TEX | 条目字节 | TEX 逻辑宽×高 | T4 数据字节 | swizzle 存储宽×高 |
|---|---:|---:|---:|---:|
| `font08_00.tex` | 8320 | 128×128 | 8192 (`0x2000`) | 128×128 |
| `font08_01.tex` | 8832 | 128×130 | 8704 (`0x2200`) | 128×136 |

- TEX 头 48 (`0x30`) 字节；`+0x10` 为纹理类型 4，`+0x12` 为 swizzled=1，`+0x14/+0x16` 为宽/高，`+0x1c` 为数据长度。每页尾部 80 字节为 CLUT 头和 16 色 alpha 调色板。
- PSP T4 swizzle 每块为 **16 字节×8 行**，每字节低 nibble 是左像素，高 nibble 是右像素。应按数据长度推导的存储高度解包，第二页不能只读逻辑 130 行。
- 名称 `font08` 指名义 8px 小字；实际排布是 **9×9 像素槽位、14 列×14 行，每页 196 字**。坐标为 `page=index//196`、`tile=index%196`、`x=(tile%14)*9`、`y=(tile//14)*9`。
- 原字并非全都局限于 8×8：`ｇｊｐｑｙ` 用到第 9 行，`ばふむもりオネ` 用到第 9 列。渲染和替换应保留完整 9×9 槽，避免裁掉笔画。
- 两页有 392 个槽，当前使用 219 个，尚有 173 个空槽。原图解 swizzle 后的观察图：`ruby-font-atlas.png`（9px 格线）。

这里以上标 `#RUBS上标#RUBE正文#REND` 的第一段统计，不把正文的字混入；当前主表共 **1649 条、1878 组** ruby。

| 指标 | 当前中文上标 |

| 字符总次数（含空白） | 4898 |
| 不同字符数（含空白） | 996 |
| 小字表有映射的不同字符 | 41 |
| 小字表无映射，排除空白 | **953 字 / 4797 字次** |
| 其中汉字 | **913 字 / 4262 字次** |
| 存在无映射非空白字符的 ruby | **1859 组 / 1636 条文本** |
| 含汉字上标的 ruby | **1765 组 / 1557 条文本** |

无映射非空白字符还包括 **38 个 ASCII 字母/句点**与 `·…` 两个符号。ASCII 集合：`.ABCEFGHILMNPRSTWabcdehiklmnorstuvwxyz`。空白另有普通空格 5 字次、全角空格 15 字次。ASCII 和空白是否被运行时转全角/特殊处理，本静态字体审计未确认；上述“无映射”不等同于已观察到具体的空白、替代框或回退表现。

最常见的缺失上标字是 `御`、`主`（各 309 次）、`爱`（126 次）、`丽`（125 次）、`丝`（124 次）。例如 `御主`、`删除`、`天线` 的正文编码均有效，但 ruby 专用表找不到对应槽。

原日文上标的对照：1830 条、2119 组；175 个不同字符中有 6 个汉字（`学工脳記録電`，各 1 字次）同样不在 ruby 表，另有空白。这说明单凭静态映射不能断言运行时对每一种缺字的具体显示行为；当前 913 字的中文需求依然明确未在资源中安装。

## 5. 建议的补字实现

1. 先完成双层 ruby 文本复核，再从最终保留的上标第一段收集所需字，删除普通日文注音后重新计算；本报告的 953 是现行翻译的上限需求。
2. 保留原 219 条，向 `ruby.bin` 追加最终所需的缺字，更新 `uint32` 数量并补齐 16 字节。**必须沿用现有正文编码 `glyph-map.json`**：原生 CP932 字如 `御` 写代码 `0x8CE4`；简体扩展字如 `爱` 经映射变为 `U+E31D`、CP932 `F4 6D`，ruby 记录前两字节写 `6D F4`，UTF-8 字段仍写目标字 `爱`。不要再为 ruby 独立分配一套 PUA 编码。
3. 新字渲染为 9×9 alpha 格，尽量把汉字主要笔画放在 8px 名义字号内，保留完整槽位；量化到 16 级，写入同一套 128px 宽、pitch9、196槽/页的 T4 atlas。`render_font_glyphs.swift` 可传 cell-size=9 和相应字号，但仍需专门检查 9px 下的汉字笔画。
4. 先填第二页剩下的 173 槽，再按需追加 `font08_02.tex` 等页。若保留全部现行需求，219+953=1172 条，共需 **6 页（比当前多 4 页）**；仅补 913 个汉字也需要 6 页。页数扩展是否存在运行时上限，应由 EBOOT 静态路径或后续实际显示确认，不能仅由 PAK 可存放多页推定。
5. 编写 ruby 专用的尺寸可变 T4/PAK 写入逻辑，保留现有元数据和调色板。正文工具的 `WIDTH=HEIGHT=256`、16×16 字格、`FONT_PAGE_SIZE=256` 与这里不兼容。现有 `write_font_txb(entries, has_paths=True)` 只设置路径标志而不写 64 字节文件名，**不可直接用于这个带名字的 ruby.txb**；应按原 PAK 结构正确写名、长度和内容。
6. 对 Latin 上标，可在文本复核时统一采用现成的全角 Latin（原表已有 52 字），或在查明运行时 ASCII 路径后补 ASCII；`·` 与原表的 `・` 是不同字符。编码审计、字形非空检查、页边界（195/196/391/392）和实际显示属于补字后应确认的项目。
