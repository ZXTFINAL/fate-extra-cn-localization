# v1.3 已报告问题的根因与修复

## Issue #1：高清字库部分清晰、部分模糊

v1.2 发布的 ISO 内 `data.cpk` SHA-256 为 `255880164ddfb55e37e656ba61d23bb26c98174f03e88eace639f1d5ac7b8e4f`，但当时用于生成高清 UI/字库纹理映射的 CPK SHA-256 为 `de615b0fc29d30e5f1bbe2e869f358bdedead07350e819500b992913f2426786`。二者不一致，PPSSPP 按游戏纹理哈希查找替换时只能命中部分字库页；没有命中的页仍显示 ISO 内低分辨率原图。这解释了“有的字清楚、有的发糊”，不只是渲染分辨率设置问题。

v1.3 的正文/UI/注音/诗文字库映射均从最终 CPK 重建。标准 ISO、PPSSPP ISO 和两个合并纹理包的 manifest 记录相同 CPK SHA-256：`7505dc81e9190bdbc2247fd2aee5ddcf3400e0f2ea17b9d8fc885cdfb4f9596b`。合并包构建器会比较 UI 包和待发布 CPK；哈希不一致时直接失败。安装时必须使用同版 ISO、一个 v1.3 合并包，并清理旧版纹理目录/缓存。

本版完成的是构建与资源键静态一致性校验，没有在 PPSSPP 中重新逐场景运行；模拟器实际显示效果仍需玩家验证。

## Issue #2：将「男子トイレだ。」误译为布告栏

原文 `男子トイレだ。` 的主译文表错误地写成“墙上贴着各班级的名单。”，造成场景含义完全相反。现改为“男厕。”；紧随其后的 `今は特に用はない。` 对应“现在也没什么特别要做的事。”，语义无误，保留。该 ID 被 285 个相同原文引用复用，因此构建会把此修正应用到对应的所有同文引用。

根因还包括构建审校流程允许仅凭 ID 应用上下文补丁，未要求检查该译文来自哪个原文/引用位置。上下文审校 lane 现需同时提供匹配的 `source_jp`、存在于引用索引中的 `source_ref.file` 和 `source_ref.text_offset`；同一 lane 内冲突的重复 ID 也必须明确标记后续条目为 `supersedes`。修正同时写回正式译文主表与上下文审校记录。
