# 正文字库：补字、渲染与 4,096 上限

Fate/Extra 的正文不是系统字体渲染，而是**预烘焙位图字库**。游戏只认 `kanzi.bin` 里的"码位 → 图集索引"，没有的字就是空白或替代符。因此中文能否显示，取决于三件事同时成立：

1. 译文里的每个字都能编码成 CP932 双字节；
2. `kanzi.bin` 有该码位的记录；
3. 记录指向的图集格子里真的画着这个字。

---

## 1. 字库结构

`PRELOAD.pak` 中与正文相关的两个文件：

| 文件 | 作用 | 原大小 |
|---|---|---|
| `kanzi.bin` | 码位到图集索引的映射表 | 18,256 字节 / 3,040 字 |
| `font.txb` | T4 位图图集，16×16 格 | 394,816 字节 |

`kanzi.bin`：

```
uint32 count
record[count]  # 6 字节：CP932 小端(2) + UTF-8(3) + 0x00
```

`font.txb`：

- 每页 256×256，T4（4bpp），PSP swizzle；
- 16×16 字格，16 列 × 16 行 = **256 字/页**；
- 图集索引即全局字序：`page = index // 256`、`tile = index % 256`；
- 16 页 = 4,096 字，这是**运行时索引上限**。

---

## 2. 补字算法

`patch_fate_extra_font.py` 的流程：

```
读取原 kanzi.bin
  ├─ 建立 char → index 映射
  ├─ 统计译文需要的字符
  ├─ 对每个字符：
  │    ├─ 原生 CP932 可编码且原字库已有 → 复用
  │    ├─ 原生 CP932 可编码但原字库没有 → 分配别名
  │    └─ 原生 CP932 不可编码（简体专有字）→ 分配别名
  ├─ 在 0xE000–0xE757 中找未使用的 CP932 用户区码位
  ├─ 追加 6 字节记录
  └─ 用同一套中文字体渲染所有中文/标点字形
```

### 2.1 为什么用 CP932 用户区

游戏文本最终要变成 Shift-JIS 字节流。简体专有字（如 `爱`、`删`）不在标准 CP932 中，但有两条路：

- 扩编码表（改 EBOOT，风险高）；
- 用 CP932 用户定义区（`0xE000` 起）做**别名**：`glyph-map.json` 把 `爱` 映射到 `U+E31D`，游戏只看到 `U+E31D`，而 `kanzi.bin` 把 `U+E31D` 指向"爱"的字形。

本工程选后者：不改可执行文件，只改数据。别名范围 `0xE000–0xE757`，共 1,880 个槽，实际使用 1,571 个。

### 2.2 为什么不用原有日文字位

早期的直觉做法是"找没用的日文汉字槽覆盖掉"。这在本作不可行：

- 文本只提取了 DAT 中的剧情/系统串，**UI 图片、未提取分支、调试串仍可能引用这些字**；
- 一旦覆盖，未提取内容会显示成中文错字，且很难定位。

因此补字阶段的规则是：**原有 3,040 个字位不覆盖，中文全部走新增别名**。直到字库压缩阶段，才删除 515 个"已证明没有任何引用"的日文字（见下一节），但绝不占用仍有引用的字位。

### 2.3 渲染

`render_font_glyphs.swift`：

- 字体：`Hiragino Sans GB W6`（比常规体更接近原日文字库的笔画粗细）；
- 字格 16×16，字号 13px，留 1–2px 内边距；
- 输出 256 字节/字的 8bit alpha 位图；
- 量化到 T4 的 16 级灰度；
- 只渲染中文汉字与中文标点，日文原生字保持原样（混用两套字体会出现明显大小/粗细不一致）。

## 3. 从 4,611 压回 4,096

3,040（原字）+ 1,571（中文别名）= 4,611，超出 4,096。必须删字。

`compact_fate_extra_font.py` 的策略：

1. 统计译文（含引用权重）实际用到的字符；
2. 标记所有"仍被使用"的字；
3. 在原日文字中，挑出**没有任何引用**的 515 个汉字；
4. 删除这些字，重排索引，同步改写 `kanzi.bin` 与所有译文的别名映射；
5. 图集仍为 16 页 × 256 字。

结果：

| 指标 | 值 |
|---|---:|
| 原字库 | 3,040 |
| 扩展后 | 4,611 |
| 压缩后 | 4,096 |
| 删除的无引用日文字 | 515 |
| 图集页数 | 16 |

注意：删字会改变索引，因此**必须在所有译文定稿、`glyph-map` 冻结之后做**，且压缩后要重新生成一次 `glyph-map.json`。压缩前的映射不能用于压缩后的字库。

---

## 4. 索引与别名的冻结规则

`glyph-map.json` 是"汉字 → 私有区别名"的唯一真相。它有三个不可逆约束：

1. **已分配的别名不能改**。旧译文已按旧别名写进 DAT，改了就会整句错字。
2. **已分配的别名不能复用给另一个字**。否则同码位出现两种字形。
3. **压缩/重排后必须整体重新生成**，不能手工合并两份映射。

工程中的做法：

- 首次补字生成 `glyph-map.json` 与 `glyph-allocations.jsonl`（记录每个别名的目标字、索引、时间）；
- 日常增量只**追加**，不重排；
- 唯一的例外是**字库压缩**：它是一次显式的全局重排，必须重新生成映射并重编码全部译文；
- 每次构建把 `glyph-map.json` 的 SHA-256 写进构建报告，便于回溯。

## 5. 验证清单

| 检查 | 方法 | 期望 |
|---|---|---|
| 映射完整 | 遍历译文，`glyph_map` 后 `cp932` 编码 | 0 失败 |
| 索引一致 | `kanzi.bin` 记录数 = 图集格数 | 4,096 = 16×256 |
| 字形非空 | 每个中文字格至少有 N 个非零像素 | 无空字 |
| 别名唯一 | `glyph-map` 的值无重复 | 是 |
| 回环 | 解包 → 重打包 → 逐字节比较 | 未改页完全相同 |
| 显示抽检 | PPSSPP 开场/菜单/战斗 | 无方块、无裁切 |

字体层的错误通常不会崩溃，只会"看起来不对"，所以必须做视觉抽检。仅靠字节校验通过不等于字能看清。

## 6. 常见坑

| 现象 | 根因 | 修法 |
|---|---|---|
| 中文全是方块 | 别名记录了，但图集没画 | 检查渲染输出与页索引 |
| 部分字变成日文字形 | 别名与原有码位冲突 | 检查 `glyph-map` 是否复用了已占用码位 |
| 字被裁掉下半 | 字号过大或基线偏移 | 降字号/调 baseline，保留 1px 边距 |
| 字迹过细/过粗 | 字体权重不匹配 | 用 W6，不用 W3 |
| 游戏读取越界 | 字数超过 4,096 | 压缩字库或删无引用字 |
| 旧文本整句错字 | 压缩后重排了索引，但旧译文未重编码 | 重新生成映射并全量重建 |
