# 踩坑清单

按"症状 → 根因 → 修法"记录。每条都来自实际构建或审计，不是假设。

---

## A. 文本与指针

### A1. 中文只显示前几个字，后面拖着日文残字

**根因**：短译文只覆盖了原串的前半段。部分渲染器按存储字符数读取，不按 NUL 停止。

**修法**：新串 ≤ 原串时，把原槽（含原 NUL）**全部清零**再写新串。

```python
slot = len(old_bytes) + 1
data[o:o+slot] = new + b"\0" * (slot - len(new))
```

### A2. 改了一句，另一个场景还是日文

**根因**：同一 ID 在多个 DAT 中复用，只改了一个 `file` 的指针。

**修法**：按 `refs.jsonl` 遍历该 ID 的**全部** ref，每个 `pointer_offsets` 都改。

### A3. 游戏在某句崩溃

**根因**：长串追加后指针算错；或把指针写到了非字符串区；或 DAT 末尾未对齐。

**修法**：追加前记录 `new_offset = len(data)`，写完 NUL 再 `pack_into`；DAT 末尾 16 字节对齐；用解析器重读验证。

### A4. 译文被写到错误位置

**根因**：`text.jsonl` 与 `refs.jsonl` 不同源（一个是新表，一个是旧引用）。

**修法**：两者必须同一轮生成；增量修订先用旧译文编码做字节比对，不一致即中止。

### A5. 改了提取规则后所有批次失联

**根因**：`id` 由源字节哈希生成，改提取逻辑（去空白、改解码）会改 ID。

**修法**：提取规则变更要做 ID 兼容对照；必要时保留旧 ID 映射，不直接重算。

## B. 正文字库

### B1. 中文全是方块

**根因**：`glyph-map` 有别名，但图集没画对应字形，或页索引算错。

**修法**：检查 `kanzi.bin` 记录 → 索引 → 页/格坐标 → 图集非空；跑字形非空校验。

### B2. 游戏读取字库越界

**根因**：字数超过 4,096（16 页 × 256）。

**修法**：`compact_fate_extra_font.py` 删除无引用日文字；压缩后重新生成映射并全量重建。

### B3. 未提取的 UI 出现中文错字

**根因**：复用了原日文字位，而那些字仍被未提取内容引用。

**修法**：原有 3,040 个字位一个不动，中文全部走 `0xE000` 用户区别名。

### B4. 升级字库后旧文本整句错字

**根因**：压缩/重排改变了索引，但旧译文仍按旧别名编码。

**修法**：别名只追加不重排；必须重排时，重新生成 `glyph-map` 并全量重编码。

### B5. 中日字形混排，大小不一

**根因**：中文用原生 CP932 字位（日文字形），生僻字用中文字体渲染。

**修法**：所有中文汉字/标点统一用 Hiragino Sans GB W6 重新渲染，日文原生字保持不动；不要用 W3（过细）。

## C. 诗文（poem）

### C1. 章节卡中文碎成偏旁

**根因**：按 16×16、256 字/页重建，运行时按 14×14、324 字/页采样。

**修法**：格 14×14、18×18/页、`perPage=324`；UV 用 `(index%324%18)*14`、`(index%324//18)*14`。

### C2. 只有部分章节正常

**根因**：`poem.pak` 在 CPK 中有 12 份副本，只替换了一份。

**修法**：按哈希找出全部副本，统一替换。

### C3. 章节卡文字散开/不显示

**根因**：对 `0x0126` motion 文本插了换行，改变了动画布局；或用了正文字库别名。

**修法**：motion 文本不插换行；使用诗文专用映射表。

### C4. 诗句最后一行被裁

**根因**：14×14 格全部画满，采样矩形是 `u..u+13`，边界像素被邻格影响。

**修法**：墨迹控制在 13×13，最后一列/行透明。

## D. ruby 小字

### D1. 修了文本，小字还是不显示

**根因**：`ruby.bin`/`ruby.txb` 是原版，219 字全是假名+Latin，0 汉字。

**修法**：扩容到 518 字 / 3 页；新字沿用正差别名。

### D2. 小字缺笔画/被裁

**根因**：按 8×8 裁切，但原字用到第 9 行/列（`ｇｊｐｑｙ`、`ばふむもりオネ`）。

**修法**：保留完整 9×9 槽；汉字主体控制在 8px 内但不要裁槽。

### D3. 重写 `ruby.txb` 后游戏读不到

**根因**：它是带 64 字节路径名的 PAK；`write_font_txb(has_paths=True)` 只设标志不写名字。

**修法**：按原结构写 `count/flags/sizes/align/64字节名字/payload`。

### D4. 第二页解包高度不对

**根因**：逻辑高 130，T4 存储高 136；只按逻辑高解 swizzle 会错位。

**修法**：由 `data_size` 推导存储高度。

### D5. 上下层重复/缺失

**根因**：把 ruby 当普通文本，重复译成同一个词，或漏掉 `#REND`。

**修法**：按 929 种组合逐类决定；结构校验组数与 `#REND`。

## E. 纹理与 UI

### E1. TXB 重写后条目错位

**根因**：带路径的 TXB，名字在 payload 前，不在头部；只改长度表不写名字。

**修法**：保持 `count/flags/sizes/align/name+payload` 顺序。

### E2. 花屏/颜色错乱

**根因**：丢失唯一块、调色板长度算错、CCT 空块计数错。

**修法**：CCT 20 字节头 + `int16` 索引，`-1` 为空且不计入 count；调色板按色数/模式计算，不信 `palByteSize`；未修改块保持引用。

### E3. 无改动也发生了变化

**根因**：解码→编码不是幂等。

**修法**：先做回环校验；不通过就不允许编辑。`fate_extra_texture.py` 已内置。

### E4. 改了保存界面，第二章又变日文

**根因**：同一 TXB 在多个包中重复，只改了一份。

**修法**：按整文件 SHA-256 分组，编辑后分发到所有别名路径（v15：466 目标 → 260 别名包）。

### E5. 难度选择页被旧版本覆盖

**根因**：重复输出 `modeselect/modeselect.txb`，用旧翻译覆盖 v14 已完成资源。

**修法**：该文件不输出，只输出需要变更的其他资源。

### E6. OCR 把图标当文字擦掉

**根因**：只信 OCR bbox。

**修法**：OCR 仅找候选，必须对照 PNG 人工确认矩形；只擦声明区域，保留按钮/边框/英文装饰。

### E7. 教程截图里的字还是日文

**根因**：截图是原游戏画面，不是运行时 UI 纹理。

**修法**：区分"教程标题/正文"与"截图内部 UI"；后者需按精确矩形单独补，不能声称已全译。

## F. ISO 与构建

### F1. 写回后黑屏/找不到资源

**根因**：ISO9660 目录记录未更新；或文件名变成大写。

**修法**：更新目录记录 extent/size 与 PVD 卷大小双端字段；用 `patch_fate_extra_iso_case.py` 恢复小写 `data.cpk`。

### F2. CPK 变大后越界

**根因**：新 CPK 超过原 extent，但未允许卷增长或未更新卷大小。

**修法**：`--allow-volume-growth`；确认占用的是空闲扇区；更新 PVD `+80/+84`。

### F3. 重建后条目偏移全错

**根因**：只改了内容，没重写 TOC 的 `FileOffset/FileSize/ExtractSize` 和头部 `EtocOffset/ContentSize`。

**修法**：按 `AbsoluteOffset` 顺序重排，2,048 对齐，最后回填 TOC/ETOC。

### F4. 未变更资源被旧版本顶回

**根因**：从 `work/extracted/` 重新打包，而该目录是旧快照。

**修法**：未变更成员直接从源 CPK 读原始字节；增量修订以"可用的旧 CPK"为基线。

### F5. ETOC 损坏

**根因**：尝试重建 ETOC。

**修法**：原样搬运，只改偏移；没有完整规格前不要重建。

## G. 流程与判断

### G1. "覆盖率 100%"不等于完成

**根因**：只统计非空 `zh_cn`，不检查语义、字库、图片、实机。

**修法**：分层报告：结构 / 语义 / 运行时；每层单独给数字和边界。

### G2. 检索命中被当成错误批量改

**根因**：把"含 `しか`"、"含人称"当成错误。

**修法**：检索只产生候选，必须逐句读上下文确认。

### G3. 静态审计被写成实机验证

**根因**：报告措辞不严谨。

**修法**：明确写"静态资源采样/未启动模拟器"；只有实际走查过的路径才写"运行通过"。

### G4. 未读的分片被标记已审

**根因**：用脚本批量勾选。

**修法**：进度文件只记录真实读过的 ID；lane 2/3 为空就写 0。

### G5. 一次改太多，出问题无法定位

**根因**：文本、排版、字体、图片混在一次提交。

**修法**：一类变更一个脚本、一次提交、一份报告；每步保留 `text.pre-*.jsonl` 快照。

## H. 一句话总结

> 这个工程里几乎每个 bug 都来自"把某一类资源的假设套到另一类上"。
> 文本有文本的长度约束，字库有字库的网格，纹理有纹理的块结构，ISO 有 ISO 的目录。
> **先证明格式，再写代码；先做回环，再改内容；先读上下文，再改译文。**
